# Advanced search and runtime boundaries

For change-direction retrieval when both revisions are available and indexed, use `retrieve --file AFTER --avoid-file BEFORE --under SCOPE --json`. This ranks material aligned with the new-minus-old representative direction without inference. Treat it as exploratory context selection, not a textual diff, causal impact map or importance score. The index has no automatic revision history; do not assume an overwritten file retains its earlier vector.

For literal set operations on retrieved file lists (different from distance composition), pass a JSON specification to `weft query --spec - --json` on stdin. Leaves: `{"op":"text","query":"question","top":50,"min_score":0.3}`, `{"op":"file","path":"/absolute/reference.md","top":50}`, `{"op":"path","query":"terms","under":"/absolute/folder","kind":"text"}`. Compose with `{"op":"union|intersection|difference","args":[LEFT,RIGHT]}` using an actual operation name. Sets use exact file-path identity. Text/file leaves are bounded retrieval sets, not logical truth predicates; use metadata leaves for exact exclusions. Intersection/difference retain the left ranking; union uses reciprocal rank fusion. Output top applies after set evaluation. Prefer a semantic/file leaf first when chunk evidence is needed. Specifications are limited to 1 MiB, depth 16 and 128 nodes.

Background scans default to 25% inference duty cycle; explicit `--duty-cycle 1..100` adjusts it. User-requested controls: `weft control pause|resume|stop`, `weft control limit --duty-cycle 20`. Pause releases the model after current inference; resume may reload it. Stop preserves committed files and skips pruning. A pause/stop request is cooperative; verify `last_scan.status` and `indexer_running` rather than treating the request as an immediate state change. No automatic file watcher or battery/thermal scheduling exists.

Native indexing chunks text (default 1,100 characters, two lines of overlap), preserves Unicode, and embeds only changed files. Keep 768 dimensions and Q8 vector storage by default; reducing dimensions needs a labeled comparison on the relevant corpus. Whole-computer scanning excludes system/runtime directories, caches, dependencies, private-key stores, `.env` files and the index itself, respects ignore files, and does not follow symlinks. Permission failures and oversized files mean coverage is not literally every byte on disk.

Supported text up to 2 MiB is indexed by content; unsupported formats, binary/non-UTF8 input and oversized files use filename-only embeddings in `--all` mode. PDF/Office/OpenDocument text and embedded-image extraction are supported as described in the main skill. Native image/audio/video encoders, OCR and media time-segment search are not implemented. Optional Python media routing is separate and unvalidated locally; do not switch to it automatically or download the full model to answer an ordinary file search.

Devices: `--device auto|cpu|metal:0|cuda:0`; `mps` aliases direct Metal. CUDA has not been validated on NVIDIA hardware here. Device changes do not require reindexing. Native inference's token limit is 2,048 including prefixes; use smaller chunks if exceeded rather than silently truncating. All inference and search stay local; the database stores vectors, paths and line ranges without copying source text.

On one-shot queries, `weft prepare` stores a validated GGUF tensor/tokenizer-layout sidecar next to the model; the original GGUF still supplies every weight. It can be regenerated after replacing the model. For repeated WQL text queries, `weft q 'all("A","B") top 10'` starts an idle-limited local inference daemon; socket identity includes index/model/device and is limited to the current Unix user. `weft q 'file("/path/to/indexed.md") top 10'` needs no daemon. A daemon may incrementally scan explicitly registered `weft view` paths on idle shutdown; avoid registering a path without authorization to index it. See `eval/M4PRO_PERFORMANCE_2026-10-12.md` for cold-load, memory, and exact scan measurements and limitations.
